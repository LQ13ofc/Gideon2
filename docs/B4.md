# B4 — pacote Linux offline relocável (Core + App + Base)

Escopo B4.1: diretório de pacote autocontido, relocável, verificável por hash,
que roda S1 (wake replay→STT→comando sandbox→TTS virtual) a partir de um prefixo
diferente do repositório, SEM acesso ao repositório/target/uv do host.
Fora de escopo: Flatpak/portal, Wayland real, áudio físico, autostart/systemd,
instalação no host do usuário, assinatura/atualização de pacote (B4.2+).

## Layout `gideon-base-<versão>/`

bin/gideon-base (release), bin/gideon-app (launcher da UI), scripts/ (somente
workers e app/: wake_worker, stt_worker, tts_worker, command_worker),
app/ (QML+bridge+visual), runtime/python (cópia do CPython uv usado pelos venvs),
venvs/{a1,stt,tts,ui} (cópias com bin/python relativo→runtime e pyvenv.cfg home
reescrito), assets/ (somente runtime: modelo wake `asset_root`, VAD, modelo STT,
TTS root/config/voz/tokenizer; NENHUM corpus de fixture/QA),
templates/ (manifests com marcador @PREFIX@), PACKAGE.json (versão, commit,
target, sha256+size de cada arquivo, sem symlinks fora do prefixo).

## Contrato

1. Core ganha `--home ABS_DIR` (padrão: CARGO_MANIFEST_DIR para dev). Substitui
   env!("CARGO_MANIFEST_DIR") em transport.rs (script dir e bind). Absoluto,
   diretório, não symlink; scripts resolvidos como `<home>/scripts/<worker>.py`.
2. Rust continua exigindo caminhos absolutos e hashes de pack: o pacote não
   relaxa validações. `bin/gideon-configure PREFIX_STATE` renderiza templates
   substituindo @PREFIX@ pelo prefixo real em diretório de estado privado (0700),
   recalcula os pins do pack e grava `pack.json`; nunca escreve fora do estado.
3. `bin/gideon-core` (launcher sh) = configure idempotente + exec do Core com
   `--home`, `--base-pack`, `--tts-virtual`, `--commands-sandbox`. Sem rede,
   sem download, sem instalar plugin/LLM no first-run.
4. Verificação de integridade: `gideon-verify` recalcula PACKAGE.json; qualquer
   arquivo alterado/ausente/extra → falha fechada e código de saída ≠ 0.
5. Gate verify_b4_package.py: constrói pacote em dir efêmero, move para prefixo
   NOVO (nome diferente), roda Core em bwrap onde o repositório e ~/.local/share/uv
   NÃO estão montados (somente prefixo + /usr + estado privado), executa S1
   completo por PCM virtual, hub catálogo+aprovação+import+install+remove,
   restart, adultera um arquivo → verify falha. Regressões Base no mesmo binário.

## Contrato B4.2 — instalação versionada, update/rollback e perfis

Instalação de usuário SEM tocar o host pessoal: tudo sob `INSTALL_ROOT`
(absoluto, 0700, dono, não symlink, socket `INSTALL_ROOT/profiles/<p>/core/core.sock`
< 108 bytes). Layout: `versions/<versão>-<commit8>/` (pacotes B4.1 intactos),
`current` e `previous` (symlinks relativos para versions/, trocados por rename
atômico), `profiles/<nome>/` (STATE 0700 por perfil, independente de versão),
`install.json` (ledger privado ≤16KiB, version 1, revision CAS, current,
previous, versions[{id, version, commit, package_json_sha256}]).

CLI `gideon-install --install-root ROOT <cmd>` (python stdlib, vai em bin/ do pacote):
- `install PKG`: primeira instalação; PKG deve passar gideon-verify.
- `update PKG`: exige instalado; verify de PKG falho → exit≠0 e NADA muda; mesmo id
  já instalado → recusa; mantém no máximo current+previous (remove o mais antigo
  só após commit do ledger e troca do symlink).
- `rollback`: troca current↔previous após gideon-verify do alvo; sem previous → recusa.
- `list` (JSON), `profile create NOME` ([a-z0-9_-]{1,32}), `profile list`.
- Recusa install/update/rollback se algum perfil tiver Core ativo (core.sock aceita
  conexão) com código profile_active. Falha em qualquer ponto antes do commit
  deixa current/previous/ledger intactos (injeção de falha para teste via
  GIDEON_INSTALL_FAIL_AT=stage|ledger|switch).
`gideon-launch --install-root ROOT PERFIL [args do Core]`: exige ledger válido e
current verificado; cria perfil se não existir; exec `current/bin/gideon-core
ROOT/profiles/PERFIL`. Ledger/symlink inconsistente → falha fechada, sem Core.

Perfis: STATE separado por perfil (preferências, approvals, hub, instalados); um
perfil não lê o do outro; Storage lock impede dois Cores no mesmo perfil.
Update/rollback preservam STATE; gideon-configure re-renderiza e re-pina para a
versão corrente (idempotente). Nenhuma rede, nenhum autostart, nada fora de ROOT.

Decisão de distribuição (B4.2): pacote nativo de usuário (este). Flatpak adiado:
exige portais de áudio/background e revisão do bwrap aninhado dos workers; adotar
só com evidência (nenhum hack global agora). Compatibilidade KDE/Wayland real,
áudio físico e autostart ficam para teste físico consolidado após S5.

Gate verify_b4_update.py (pacotes v1 e v2 do mesmo commit com --version diferente
via build_package.py): install; perfil alice S1 + preferência salva; update v2 com
alice preservada e S1; perfil bob isolado (padrão, não vê alice); rollback v1 com
alice preservada e S1; adulterar PKG → update recusado, current intacto; falha
injetada em cada ponto → estado intacto; update com Core ativo → profile_active;
ledger corrompido / symlink dangling / ROOT 0755 → falha fechada; nada escrito fora
de ROOT; regressões Base no mesmo binário.
