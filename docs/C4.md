# S3 / C4 — plugins de percepção e ação (C4.1–C4.6)

Fonte: Notion "S3 · Plugins e LLM Engine", Gate C4. Ordem: C4.1 screen.observe, C4.2
computer.control, C4.3 audio.advanced, C4.4 mic.advanced, C4.5 camera.gesture,
C4.6 display.manipulate. Pipeline por plugin: manifest → Hub instala → UI de permissão →
Core recebe capability → LLM usa (se precisar raciocinar) → ação em sandbox → verificação →
desinstalação → regressão S1/S2. Sensores e áudio funcionam sem LLM.

## Honestidade de backend (regra central)

Este ambiente não tem tela pessoal, portais, libei, PipeWire, webcam nem compositor para
testar. Portanto cada plugin tem DOIS backends:
- `synthetic`: mundo sintético do Core (`<BASE>/synthetic/world.json`, 0600, só com a flag
  `--agent-synthetic`) acessado por host services `synthetic.<área>.<verbo>`. É o que os gates
  exercitam. Todo resultado traz `backend:"synthetic"`.
- `real`: adapter de portal/PipeWire/libei/webcam. NÃO é implementado nem alegado: o plugin
  responde `status` com `real_backend:"unsupported"` e `reason:"needs_human_validation"`;
  nenhum código de acesso silencioso a hardware pessoal existe. Nada aqui afirma suporte
  físico, Wayland, PipeWire ou webcam. C4.6 é `UNSUPPORTED` por inteiro (nem synthetic).

## Infra genérica no Core (C4.0)

1. Host services (via `host_call`, já existente) só sob `--agent-synthetic`, cada um exige
   permissão APROVADA do plugin chamador; sem ela `permission_denied`:
   `synthetic.screen.{capture}` (perm `screen_observe`), `synthetic.input.{a11y_tree,click,type,key,focus}`
   (perm `input_control`), `synthetic.audio.{routes,set_route,app_volume,eq,denoise,state}`
   (perm `audio_route`), `synthetic.mic.{state,configure,monitor,record_start,record_stop}`
   (perm `mic_config`), `synthetic.camera.{state,optin,capture,gestures}` (perm `camera_capture`).
   Serviço sem a flag ⇒ `unknown_service`. O Core valida args estritos e tamanhos (≤ 4 KiB por resposta).
2. Mundo sintético `world.json` (version 1, ≤ 64 KiB, atômico 0600): `app{epoch,counter,text,published}`
   (o mesmo da C3, migrado para dentro do mundo SEM quebrar C3), `screen{epoch,width,height,
   windows:[{id,title,focused}],elements:[{id,role,name,x,y}]}`, `audio{routes,apps:[{id,volume}],eq,denoise}`,
   `mic{device,gain,filter,monitor,recording,indicator}`, `camera{opt_in,indicator,frame_seq,gesture}`,
   `base{mic_state,speaker_state}` (sentinela: nenhum serviço C4 pode alterá-lo).
3. Ponte tool→capability para o agente C3 (registro continua FIXO no Core; plugin não registra):
   `screen_capture`→`screen_observe.capture` (read), `ui_tree`→`computer_control.tree` (read),
   `ui_click{epoch,element}`/`ui_type{epoch,text≤64}`→`computer_control.act` (state_changing),
   `audio_set_route`/`audio_app_volume`→`audio_advanced.act` (state_changing). Só existem com
   a flag; executor exige plugin dono em execução e permissão aprovada, senão observação
   `capability_unavailable`/`permission_revoked`; isso fecha a lacuna `permission_revoked` do C3.
   Revogar a permissão/plugin no meio do run ⇒ próximo passo recebe `permission_revoked`.
4. Permissões novas são só strings de manifest (`screen_observe`, `input_control`, `audio_route`,
   `mic_config`, `camera_capture`); o UI de permissões do Hub já as mostra. Nenhuma é concedida por padrão.

## Plugins (ids não reservados: primeiro segmento da capability é o id do plugin)

Todos `runtime: python3_script`, sandbox C0, sem rede, entrega por catálogo `hub-c4.json`
(gerado por `scripts/make_c4_catalog.py`), fixtures em `tests/fixtures/c4/<id>.py`.

- C4.1 `screen_observe` 1.0.0, perm `screen_observe`, cap `screen_observe.capture` (read),
  `screen_observe.status`. Saída: `{backend, epoch, width, height, sha256, regions:[{role,name,x,y}]}`;
  screenshot é EVIDÊNCIA, nunca concede permissão nem entra como instrução ao agente (observação
  prefixada como dado não confiável). Sem grant ⇒ `permission_denied`. Cada captura gera evento audit
  `screen_capture` sem conteúdo.
- C4.2 `computer_control` 1.0.0, perm `input_control`, caps `computer_control.tree` (a11y estruturada
  primeiro), `computer_control.act {kind: click|type|key|focus, epoch, ...}`, `.status`.
  Ações tipadas; `epoch` velho ⇒ `stale_screen` sem efeito (focus freshness); verificação relê o mundo
  (`verified:true|false`). Sem visão/coordenadas cruas: click por `element` id da árvore.
- C4.3 `audio_advanced` 1.0.0, perm `audio_route`, caps `audio_advanced.state`, `.act {kind: route|app_volume|eq|denoise}`.
  Nunca toca `base.*`; teste prova sentinela intacta. Volume 0..=100, EQ preset da lista fixa.
- C4.4 `mic_advanced` 1.0.0, perm `mic_config`, caps `mic_advanced.state`, `.configure {gain, filter}`, `.monitor`,
  `.record {action: start|stop}`. Gravar só com indicador ligado e `start` explícito; sem
  gravação silenciosa; `start` sem consentimento do usuário (grant) ⇒ `permission_denied`; o indicador
  fica no estado (`mic.indicator`) e aparece no resultado. Não altera captura da Base.
- C4.5 `camera_gesture` 1.0.0, perm `camera_capture`, caps `camera_gesture.state`, `.optin {enabled}`, `.capture`,
  `.gestures`. Padrão opt-in DESLIGADO; capture/gestures sem opt-in ⇒ `opt_in_required`; indicador de
  privacidade `camera.indicator` ligado enquanto opt-in; opt-out limpa frames.
- C4.6 `display_manipulate` 1.0.0, perm `display_manipulate`, cap `display_manipulate.status` apenas:
  retorna `{supported:false, state:"UNSUPPORTED", reason:"no_compositor_api_in_environment", note:"overlay/captura não é manipulação de saída"}`.
  Nenhuma ação de manipulação existe; produto não é bloqueado.

## UI (Qt)

Página "Percepção e ação" visível se algum plugin C4 roda: cartão por plugin com estado, backend
(rótulo "SINTÉTICO — sem hardware real"), permissão exigida/concedida, `real_backend: não suportado /
pendente de validação humana`, botões de teste Capturar/Árvore (leitura), indicadores de privacidade
(mic/câmera) sempre visíveis, C4.6 com selo UNSUPPORTED. Texto PlainText. Bridge: slot
`perceptionInvoke(capability, input)` com allowlist de capabilities C4 e validação estrita das saídas.

## Gates

`verify_c4_<n>.py` por plugin (n=1..6) + `verify_c4_final.py` (S3 final: conversa LLM scriptada →
screen_capture + ui_click sintético com aprovação, UI statuses, grants, cancel, falha de provedor, revogação;
S1/S2 intactos, sentinela `base` intacta, nenhuma chave vazada). Cada gate: manifest→Hub→permissão→
capability→ação→verificação→uninstall→regressão (comandos Base A0 rápido). Matriz completa uma vez ao fim de C4.

- Desvio: as tools do agente executam no Core (checando plugin dono rodando + permissão aprovada), não via invocação da capability do plugin
  (um slot de invocação por plugin). O caminho host_call do plugin é testado separadamente.
- Skipped/honesto: repetição dos seis plugins no pacote instalado; backends reais (portal, PipeWire, libei, webcam, compositor) NÃO existem
  nem são alegados; todo resultado é `backend:"synthetic"`; validação humana pendente.
