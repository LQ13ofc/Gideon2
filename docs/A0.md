# A0 — infraestrutura mínima

Autoridade: cinco snapshots em docs/sources, lidos em 2026-10-14. Destino GitHub indicado: https://github.com/LQ13ofc/Gideon2. Nenhum remoto criado/configurado, nenhum push.

## Contratos e módulos

Uma crate Rust, um executável, runtime Tokio single-thread e um owner Core. Transport limita 8 peers, fila de 16 requests, mensagens recebidas a 4096 bytes, 5s para frame e 2s para escrita. Não há polling idle, scheduler paralelo ou manager de modelos.

Core mantém no máximo uma tarefa de sessão com deadline monotônico, cancelamento terminal, ID aleatório por boot e contador, eventos sequenciados limitados a 64, janela de IDs recentes de 128 requests. Snapshot no reconnect inclui estado autoritativo e eventos recentes; não promete histórico completo nem deduplicação permanente. Gates A2–A5 acrescentarão as transições necessárias ao mesmo owner.

Protocolo v1: snapshot, virtual_wake (somente harness explicitamente habilitado), cancel da sessão identificada e action tipada. A0 nega todas as capabilities: não há executor nem sucesso fictício. Cliente não fornece grants. Socket privado no diretório 0700, arquivo 0600, processo único via flock. A fronteira de confiança é o mesmo UID; não é isolamento de aplicativos maliciosos do mesmo usuário.

Storage/config v1 e log de metadados limitados a ~64KiB, sem voz/texto/argumentos. Config inválida preservada e startup recusado. A0 exige --root absoluto privado para evitar descoberta automática de paths pessoais; nenhuma instalação/autostart.

AudioSource/AudioSink: mono 16kHz, frame finito de até 1600 samples, timestamps monotônicos, fila virtual até 100 frames e backpressure explícita sem consumir sequência. Adaptadores de dispositivo e motores reais ainda indisponíveis; não abrir mic/speaker.

## Gate e evidência

Executável release recebe wake virtual e devolve session_started correlacionado. Casos reais: reconnect, timeout espontâneo, cancel, resultados atrasados, replay, schema inválido/oversize, peer lento, singleton, crash/restart, boot identity, shutdown, config/symlink e negação de ações.

Verificação: cargo fmt --check, check, test, clippy --all-targets -- -D warnings, build --release, scripts/verify_a0.py, git diff --check. Limites iniciais mensuráveis do Core sem engine: idle CPU <1%, RSS <32MiB (Linux /proc, janela de 2s; não benchmark acústico).

Não concluir A1 a partir de wake virtual, nem S1 a partir das interfaces. Sem CPU neural/áudio físico/AEC/Wayland verificados aqui.
